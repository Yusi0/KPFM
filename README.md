# KPFM Leaderboard (KPFM 리더보드)

KPFM 스크림(내전) 기록으로 ELO 랭킹과 개인 전적을 보여 주는 정적 웹 대시보드입니다. 서버나 데이터베이스 없이 CSV 3개를 읽어 동작하고, 그 CSV는 **원본 기록 한 파일에서 자동으로 만들어집니다.**

🔗 **라이브**: https://yusi0.github.io/KPFM/

---

## 한눈에 보기

```
 직접 편집하는 유일한 파일                      자동 생성물 (직접 고치지 않음)             웹 페이지
┌──────────────────────────┐   python build.py   ┌──────────────────────────┐   ┌─────────────┐
│ data/source/matches.csv  │ ──────────────────▶ │ lboard.csv               │──▶│ index.html  │
│ 한 줄 = 한 선수의 한 라운드 │  검증 → 계산 → 생성  │ match.csv  aftercalc.csv │──▶│ user.html   │
└──────────────────────────┘                     └──────────────────────────┘   └─────────────┘
```

- 기록을 고치거나 추가할 때는 **`data/source/matches.csv`만** 편집합니다.
- 루트의 `lboard.csv`, `match.csv`, `aftercalc.csv`, `insight.csv`는 `build.py`가 매번 새로 만드는 결과물입니다. 여기에 직접 입력하면 순위에 반영되지 않고, 다음 빌드에서 덮어써져 사라집니다.
- 계산은 항상 **원본을 첫 라운드부터 순서대로 다시 계산**합니다. 중간 라운드를 고치거나 지워도 결과가 꼬이지 않습니다.

## 새 라운드 입력하기

### 1. 원본에 행 추가
`data/source/matches.csv`를 엑셀 등으로 열어 **맨 아래에** 새 라운드의 행을 붙입니다. 저장은 `CSV UTF-8(쉼표로 분리)`로 합니다.

```csv
Round,Nickname,Team,Kills,Deaths,Map,Winning Team,Mode,Team1 Score,Team2 Score,Player Score
99,bond0822,1,26,16,suburbia,2,tdm,73,87,3459
99,sanha0929,2,29,16,suburbia,2,tdm,73,87,4014
```

| 열 | 필수 | 설명 |
|---|---|---|
| `Round` | ✅ | 라운드 번호. 마지막 번호 다음 숫자로 이어서 씁니다 |
| `Nickname` | ✅ | 게임 닉네임. **기존 선수와 철자를 똑같이** 씁니다 (대소문자 포함) |
| `Team` | ✅ | `1` 또는 `2` |
| `Kills`, `Deaths` | ✅ | 해당 라운드의 킬, 데스 |
| `Winning Team` | ✅ | 이긴 팀 `1` 또는 `2`. 무승부/취소는 `0` (아래 "알려진 한계" 참고) |
| `Map` |  | 맵 이름 소문자 (`metro`, `warehouse`, `desert`, `elevation`, `derrick`, `containers`, `suburbia` 등). 모르면 비워 둠. 웹 표시 이름은 `maps.js` |
| `Mode` |  | 모드 소문자 (`tdm`, `hp`, `koth`, `dom`, `kc`). 쉼표 금지 |
| `Team1 Score`, `Team2 Score` |  | 팀 점수. **한 라운드의 아무 행 하나**에만 써도 같은 라운드 전체에 적용됩니다 (`Mode`도 동일) |
| `Player Score` |  | 개인 점수 (인게임 스코어보드 값) |

### 2. 검증
```bash
python build.py --check
```
파일을 만들지 않고 검사만 합니다.

- **오류(진행 불가)**: 숫자가 아닌 값, `Team`/`Winning Team` 범위 오류, 같은 라운드의 중복 닉네임, 같은 라운드 안에서 서로 다른 승리 팀/모드/점수, 쉼표가 든 모드·맵·닉네임
- **경고(확인 필요)**: 승리 팀과 팀 점수 방향이 어긋남, 팀 인원 차이가 큼, **다른 라운드와 기록이 거의 같음**(같은 경기를 두 번 입력했을 가능성), **철자만 다른 비슷한 닉네임**(같은 사람이 두 계정으로 갈라졌을 가능성)

### 3. 웹에 올리기
```bash
python build.py --push
```
검증 → 웹용 CSV 3개 생성 → 바뀐 선수의 ELO 변화 표시 → `[y/n]` 확인 후 `git add / commit / push`까지 합니다. 커밋 대상은 원본 `matches.csv`와 웹용 CSV 3개뿐입니다. 푸시 후 GitHub Pages 반영까지 몇 분 걸리며, 브라우저에서는 `Ctrl+Shift+R`로 새로고침하세요.

| 옵션 | 설명 |
|---|---|
| (없음) | 검증 후 `out/` 폴더에 미리보기 생성. 웹에는 영향 없음 |
| `--check` | 검증만 |
| `--publish` | 루트의 웹용 CSV 3개를 갱신 (푸시는 직접) |
| `--push` | `--publish` + 확인 후 커밋/푸시. `--yes`로 확인 생략, `-m "메시지"`로 커밋 메시지 지정 |
| `--strict` | 경고도 오류로 취급 |

### 문제가 생기면
| 증상 | 원인과 해결 |
|---|---|
| "다른 프로그램이 사용 중이라 쓸 수 없습니다" | 엑셀에서 `match.csv` 등을 열어 두었거나 OneDrive 동기화 중입니다. 닫고 다시 실행하세요. 이 경우 파일은 하나도 바뀌지 않고 커밋도 하지 않습니다 |
| 입력했는데 순위가 안 바뀜 | 루트의 `match.csv`를 고치지 않았는지 확인하세요. 입력은 `data/source/matches.csv`입니다 |
| 사이트가 그대로임 | 푸시 후 몇 분 기다리고 `Ctrl+Shift+R`. `git log origin/main`으로 푸시 여부를 확인하세요 |
| 경고가 나옴 | 위 "경고" 항목 참고. 의도한 것이면 그대로 진행해도 됩니다 |

## ELO 공식 (`rule_v2`)

한 경기가 끝나면 선수의 ELO는 `새 ELO = 기존 ELO + 팀 승패 점수 + 보정된 개인 성과 점수`로 바뀝니다. 모든 라운드에 같은 공식을 적용합니다.

| 항목 | 내용 |
|---|---|
| 기대승률 | 우리 팀 평균 ELO 대 상대 팀 평균 ELO (민감도 400). 개인 ELO는 쓰지 않음 |
| 승패 점수 | `K × (결과 − 기대승률)` (표준 ELO). 같은 팀이면 같은 점수. 지면 강한 팀이 더 많이 잃음 |
| K | 첫 5경기 `50 × 1.5 = 75`, 이후 30에서 점차 감소(하한 15) × 1.5 = 하한 22.5 |
| 성과 점수 | `(0.2×킬 − 0.07×데스)`에서 **그 라운드 전체 선수 평균을 뺀 값 × 2**. 평균을 빼서 전체 합이 0에 가깝고 ELO가 계속 부풀지 않음 |
| 시작 ELO | 1500 |
| 무승부 | `Winning Team = 0`인 라운드는 ELO, 승패, 킬/데스, 경기 수에 반영하지 않음 |
| 기록만 하는 것 | 개인 점수, 팀 점수, 모드는 저장만 하고 공식에는 쓰지 않음 (표본이 아직 적음) |

**배치**: 5경기 이하는 배치중으로 봅니다. 계산은 같지만 K가 커서 빠르게 제자리를 찾습니다. 정식 티어는 6경기부터를 기준으로 합니다.

**티어** (100점 단위): 점수 구간은 `Copper 3 (~699)`부터 시작해 `Gold 3 = 1500~1599`, `Platinum 3 = 1800~1899`, `Diamond 3 = 2100~2199`를 거쳐 `Champion (2400~)`까지 19단계입니다. 각 색마다 3 → 2 → 1 순서로 올라갑니다.

> 예전 공식(2024년 `elo.py`)은 활동량에 비례해 ELO가 쌓이는 구조였고(경기당 평균 +4점의 킬 보너스), 개인 ELO 기준 기대승률 때문에 약한 선수가 크게 흔들렸습니다. 2026년 10월에 전체 기록을 새 공식으로 다시 계산했습니다. 근거는 `analysis/`의 스크립트로 다시 확인할 수 있습니다.

## 도구

| 명령 | 설명 |
|---|---|
| `python stats.py "닉네임1, 닉네임2"` | 유저 통계. 공백/쉼표/쉼표+공백 어느 쪽으로 구분해도 되고 `all`은 전체. 대소문자 무시, 오타는 비슷한 닉네임을 제안 |
| `python stats.py all --since 99` | **99라운드 이후만** 따로 집계한 구간 리더보드 (구간 경기수, 승패, K/D, 현재 ELO, 구간 시작 전 대비 변화) |
| `python tiers.py --since 93` | 내전용 무기 제한 티어표 **초안** (현재 ELO 순위와 구간 성과 순위의 평균을 5개 티어로 나눔). `--out 파일.csv`로 저장해 사람이 고쳐 쓰는 용도 |
| `python analysis/formula_change_report.py` | 공식을 바꿨을 때 기존 대비 변경표 (TOP10, 티어 분포, 오른/내린 선수, 배치 선수) |
| `python analysis/player_report.py 닉네임` | 한 선수의 ELO가 어떻게 쌓였는지 (승패 점수 / 성과 점수 분해, 시기별 실력, 비교) |
| `python analysis/formula_analysis.py` | ELO 공식 후보 비교 (승패 예측력, 인플레이션, 순위 변화) |
| `python analysis/k_sweep.py` | K 배율과 성과 배율에 따른 변동폭/예측력 |
| `python analysis/score_signal.py` | 개인 점수와 팀 점수가 승패나 K/D 외에 담은 정보가 있는지 |

내전 티어표는 공식 랭킹과 **별개의 운영용 임시 자료**입니다. 참여 5경기 이하인 선수는 "임시"로 표시되고, 최종 티어는 사람의 관찰을 우선합니다.

## 웹 페이지 기능

디자인은 주황 포인트 하나와 따뜻한 회색 계열 중립색으로 통일했습니다. 색 값은 `ui.css` 맨 위의 변수만 고치면 됩니다.

### 랭킹 대시보드 (`index.html`)
- **표형 랭킹**: 순위, 닉네임, 티어(색 점 + 이름), ELO와 티어 눈금자(현재 100점 구간 안의 위치), KDR, 승률, 경기 수. 5경기 이하는 `Placement n/5`로 표시하고 6경기부터 순위가 붙습니다.
- **보기 전환 (Wide / Compact)**: 우측 상단 토글. Wide는 넓은 앱 화면, Compact는 예전의 좁은 카드형입니다. 1024px 미만에서는 항상 Compact이며 선택은 브라우저에 저장됩니다.
- **실시간 검색**: 닉네임 입력 시 자동 완성 목록으로 바로 필터링합니다.
- **팀 메이킹 로비**: 카드의 `+` 버튼이나 검색으로 플레이어를 로비에 담으면, ELO 기준으로 두 팀(Phantom, Ghost)의 평균 ELO 차이가 최소가 되도록 자동으로 나눕니다. 로비에 담은 선수는 목록 맨 위로 올라옵니다.
- 다크/라이트 테마 전환.

### 보정값과 한 줄 설명 (`insight.py`)
- **보정값**: 상대와 팀원의 강도를 빼고 본 킬/데스 성적입니다. 1.00이 평균이고, 1.30이면 비슷한 상대 기준 평균보다 킬/데스 비율이 약 30% 높다는 뜻입니다. 화면에서 점선 밑줄 글자를 누르면 같은 설명이 뜹니다.
- **계산**: `성적 = 내 실력 - 상대 평균 실력`으로 보고 모든 선수를 한꺼번에 풉니다. 상대의 실력도 그 상대가 만난 상대로 검증되므로 한 겹이 아니라 전체 연결을 따라 정해집니다. 경기 수가 적은 선수는 1.00 쪽으로 당깁니다. 승패와 ELO는 쓰지 않습니다.
- **한 줄 설명**: AI가 아니라 규칙과 문장 틀로 만듭니다 (같은 데이터면 같은 문장). 5경기 이하는 판단을 보류하는 문장만 나오고, 6~9경기는 순위 비교 문장을 쓰지 않습니다. 문장에는 쉼표를 쓰지 않습니다 (웹이 CSV를 쉼표로 나누므로).
- 알려진 한계: 킬/데스만 보므로 맵과 모드 차이, 역할 차이는 반영되지 않습니다. 보정값은 ELO와 다른 질문(누구와 붙어서 얼마나 잘했나)에 답하는 참고 지표입니다.

### 플레이어 상세 (`user.html`)
- **프로필 요약**: 순위(6경기 이상만), ELO와 티어 눈금자, KDR, 경기당 킬, 승/패/승률, 누적 경기 수.
- **트렌드 차트 (Chart.js)**: 100점 티어 구간을 눈금으로 깐 ELO 추이(주황 선 하나)와 작은 누적 KDR 추이. 드래그로 확대, 더블클릭으로 초기화.
- **맵별 전적**: 맵마다 플레이 수, 승리 수, 승률. 맵 표시 이름은 `maps.js`에 모여 있습니다 (`Metro`, `Warehouse`, `Desert Storm`, `Elevation`, `Derrick`, `Containers O' Fun`, `Suburbia`). **새 맵이 생기면 `maps.js`에 한 줄만 추가**하세요. 없는 맵은 CSV에 적힌 소문자 이름이 그대로 표시됩니다.
- **매치 기록**: 라운드별 킬/데스/ELO 변동. 행을 누르면 양 팀의 기록과 팀별 MVP(ELO 상승이 가장 큰 선수)가 모달로 나옵니다.

웹은 CSV를 **헤더 이름으로** 읽고 줄을 `,`로 단순 분리하므로, 모든 값에 쉼표가 들어가면 안 됩니다 (검증이 막아 줍니다).

## 알려진 한계

- **무승부(`Winning Team = 0`)를 웹이 지원하지 않습니다.** 계산 쪽은 문제없이 건너뛰지만, `user.html`은 승패를 `Team == Winning Team`으로만 판단해 무승부를 패배로 보여 주고, 무승부 라운드에는 ELO 기록이 없어서 매치 기록과 ELO 추이의 짝이 어긋날 수 있습니다. 무승부를 실제로 입력하기 전에 웹을 고쳐야 합니다.
- **개인 점수, 팀 점수, 모드**는 모드마다 단위와 산식이 달라 아직 ELO에 반영하지 않습니다. 기록을 계속 쌓고 `analysis/score_signal.py`로 다시 확인합니다.
- 팀 이름 표시(Phantom/Ghost)는 웹에 고정되어 있습니다.

```
├── aftercalc.csv         # (생성물) 라운드 직후의 ELO
├── insight.csv           # (생성물) 선수별 보정값과 한 줄 설명
├── insight.py            # 보정값 계산과 문장 규칙 (기준값은 맨 위 CONFIG, `python insight.py`로 전체 확인)
├── data/source/
│   ├── matches.csv       # ★ 원본: 이 파일만 편집
│   └── CORRECTIONS.md    # 원본을 정정한 기록 (무엇을 왜 바꿨는지, 예전 라운드 번호 대응표)
├── engine.py             # ELO 계산 엔진과 검증 (공식은 여기의 rule_v2)
├── build.py              # 검증 + 웹용 CSV 생성 + 커밋/푸시
├── stats.py              # 유저/구간 통계
├── tiers.py              # 내전 티어 초안
├── analysis/             # 공식과 점수의 근거 분석 (데이터가 늘면 다시 실행)
├── tests/                # 검증 + 기준 데이터(baseline)
└── backup_20261012/      # 2026-10 리팩토링 직전 스냅샷 (예전 DB, CSV, elo.py)
```

원본을 정정할 때는 `data/source/CORRECTIONS.md`에 이유와 변경 내용을 남깁니다. 정정 전 상태는 깃 이력으로 되돌릴 수 있습니다.

## 로컬에서 웹 보기

브라우저 보안 정책(CORS) 때문에 CSV를 읽으려면 간단한 웹 서버가 필요합니다.

```bash
npx http-server -p 8080 -c-1
```

`http://localhost:8080/`으로 접속합니다. (`-c-1`은 캐시를 꺼서 변경이 바로 보이게 합니다.)

Python 스크립트는 Python 3.10 이상이면 됩니다.
